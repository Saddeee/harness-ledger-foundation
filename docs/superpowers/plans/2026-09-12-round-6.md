# Round 6 Implementation Plan — wired writes, undo/cancel/remove, clean cards, demo isolation, paired tests

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Sonnet 5 for every task; Haiku 4.5 only for copy-only sub-steps a task explicitly delegates. Never Opus, never Fable.

**Goal:** Every free action (add, undo, remove, re-add, restore, wording change, sync) calls Lovable when pressed and reports the result on screen; the schedule runs inside the app; cards have one clean action bar and one verdict per rule; demo data can never feed a real write; and a rule can be tested for real in a temporary copy of the project, judged side by side, with the cost recorded.

**Spec:** `docs/superpowers/specs/2026-09-12-round-6-wired-writes-controls-paired-tests.md` (§2–§8). Round-4 design detail for the paired test: `docs/superpowers/specs/2026-09-11-round-4-analysis-proof-outcomes.md` §3 and `docs/superpowers/specs/explorations/proof-and-outcomes.md` (read its platform-fact correction: MCP cannot remix at a message or delete; REST can).

## Global Constraints
- Same as round 5 (Node 22; `npm run harness:build` after `harness/src` changes; the UI fetches only the six harness routes; the web app imports the harness only through `harness/src/adapter.ts` and `src/lib/server/harness-runtime.ts`; keys/tokens never in SQLite/responses/logs; every `<details>` collapsed; touched files eslint-clean; `cd harness && npm test` (467 at start), `npm run typecheck` both packages, `npm run build` green per task; commit per task with the Co-Authored-By / Claude-Session trailer; path-limited commits; vocabulary Sync / Analysis / Suggestion / Rule; no "improvement"/"miner" in copy; no credit numbers in copy except measured ones).
- **Migration v12 is owned by Task 1 only.** Store/improvements additions in delimited `// ---- Round 6 Task N ----` blocks; re-read before editing.
- **No test touches Lovable.** The REST client and the runner are tested against a local fake HTTP server; MCP writes against the existing fake client. The owner's project is touched only in Task 7 (free writes, authorised) and the first paired test is the owner's press.
- **Nothing spends credits without the owner pressing "Start test" on one rule.** `chat` on a live (non-copy) project is forbidden by construction (the REST client's `chat` refuses a project id that is not a copy created by this run).
- Copy on every result must say what happened: "Written to Lovable 19:05" / the exact reason. The phrase "next sync" is banned from UI copy (structural test).

## Order
1 → 2 → (3 ∥ 4 ∥ 5) → 6 → 7. Tasks 3/4/5 share `improvement.tsx` only between 3 and 4 — 4 waits for 3's commit; 5 is harness-only.
